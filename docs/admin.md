# Админка

Адрес после деплоя: https://api.valerochkagym.tech/admin/.

## Возможности

- Сводка пользователей, записей, активных сессий и последних действий.
- Поиск по email, названию или UUID, пагинация, фильтр владельца и удалённых записей.
- Пользователи: подтверждение email, способы входа, дата регистрации, данные и сессии.
- Упражнения: создание и редактирование названия, группы, типа, оборудования, карты мышц
  (основная / вторичная / стабилизатор), признаков пользовательского упражнения и проверки карты.
- Залы: создание и редактирование названия, оборудования и доступных упражнений.
- Программы, тренировки, замеры и расписание: просмотр, включая все поля записи.
- Завершение всех сессий выбранного пользователя с указанием причины.
- Журнал изменений: автор, владелец, время, причина, содержимое до и после.

Общего каталога пока нет: каждая запись принадлежит одному пользователю. Администратор
явно выбирает владельца. Массовая замена каталога, удаление аккаунтов и выдача ролей
через интерфейс не предусмотрены.

## Первый администратор

Аккаунт должен уже существовать и иметь подтверждённый email. Можно предварительно войти
через Google в Android-приложении. Роль по умолчанию выключена для всех, включая старые аккаунты.
После установки новой миграции оператор сервера запускает:

    # Замените email на аккаунт владельца.
    sudo /opt/valerochkagym/admin-role.sh grant owner@example.com
    sudo /opt/valerochkagym/admin-role.sh revoke owner@example.com

Скрипт использует /opt/valerochkagym/compose.production.yaml и root-only .env.
CD устанавливает скрипт из scripts/admin-role.sh в /opt/valerochkagym/admin-role.sh.
При ручной установке достаточно доставить только этот файл: Gradle и исходники не нужны.
При отсутствии подтверждённого аккаунта операция завершается ошибкой и откатывается.
Скрипт не создаёт пользователей и не подтверждает email. Назначение/отзыв попадают в аудит
как operator@localhost; старые браузерные сессии этого администратора удаляются.
Пароли и Google-привязки не меняются.

## Вход и защита

Вход через Google или email/password того же аккаунта. Админка не регистрирует новые
email-аккаунты и не выдаёт роли автоматически. Google-токен проверяется существующим
валидатором подписи, issuer, audience, verified email и одноразового nonce.

Для Google Web-входа добавьте https://api.valerochkagym.tech в **Authorized JavaScript origins**
текущего Web OAuth client в Google Cloud Console. Client ID остаётся GOOGLE_CLIENT_ID.
Для локальной проверки добавляется отдельный localhost origin с портом.
[Требования Google](https://developers.google.com/identity/gsi/web/guides/get-google-api-clientid).

Браузерная сессия живёт 8 часов. Cookie:

    __Host-gym-admin; Secure; HttpOnly; SameSite=Strict; Path=/

Access/refresh-токены API не возвращаются браузеру и не сохраняются в localStorage/sessionStorage.
Роль, подтверждение email, срок и отзыв базовой сессии проверяются на каждом admin API запросе.
Сброс пароля и отзыв сессий закрывают также доступ к админке.

Все изменения требуют точного Origin и JSON. После входа добавляется привязанный к
сессии X-CSRF-Token; заголовок нельзя получить с другого origin. Для отдельного размещения
задайте ADMIN_ORIGIN (по умолчанию https://api.valerochkagym.tech).
Обычный Bearer-токен Android не открывает admin API. CORS выключен; выдаются CSP,
запрет встраивания и Cache-Control: no-store. Действуют rate limits и предел admin JSON 256 KiB.
Страница входа и статические файлы доступны без авторизации, данные — только после проверки роли.
[Справка Spring Security о CSRF](https://docs.spring.io/spring-security/reference/7.0/servlet/exploits/csrf.html).

## Сохранение и синхронизация

Редактор передаёт baseRevision и operationId. Изменение применяется через тот же SyncService,
что и Android: увеличивается revision, проверяются поля, UUID-ссылки, оборудование программ
и активных тренировок. Чужие ссылки и недоступное оборудование не сохраняются.
При конфликте возвращается 409, форма остаётся открытой; актуальная версия загружается только
явным действием, без автоматической перезаписи.

Повтор после потери ответа отправляет тот же пакет. Сохранение и запись аудита атомарны.
При ошибке не остаётся ни частичного изменения, ни успешной строки аудита.
Android получит запись при следующей синхронизации; активная тренировка по-прежнему
откладывает sync до завершения.

Аудит не содержит паролей, кодов и session tokens. UUID/email автора и UUID владельца
сохраняются после удаления аккаунта для расследования административных действий.
Данные до/после содержат только редактируемые упражнения и залы. Это отдельная история,
а не механизм отката; восстановление записи из старой версии в UI пока не реализовано.

## Проверки и разработка

UI — статические HTML/CSS/JavaScript в src/main/resources/static/admin, внутри JAR.
Отдельный frontend-сервис и Node.js в production не нужны.

    ./gradlew check bootJar
    npm ci --ignore-scripts
    npm test

GitHub Backend checks запускает оба набора тестов. JVM HTTP-тесты работают с настоящим
PostgreSQL/Testcontainers и Liquibase; DOM-тесты jsdom проверяют формы и обращения к API,
но не заменяют визуальную проверку настоящего браузера. Google-вход на реальном аккаунте
требует OAuth origin и назначения роли.

Для локального запуска после настройки БД:

    ADMIN_ORIGIN=http://localhost:8099 SERVER_PORT=8099 ./gradlew bootRun

Secure cookie требует HTTPS; исключения браузеров для localhost различаются.
Production-конфигурацию cookie ради локальной проверки не ослаблять.
